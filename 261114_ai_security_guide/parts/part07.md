## 7-2. 방어는 왜 한 겹으로 안 되는가?

**Q.** "시스템 프롬프트에 위험한 명령은 실행하지 말라고 적어 두면 되지 않나?"

**A.** 처음엔 그렇게 생각하기 쉽다. 그러나 Part 5에서 본 대로 LLM은 지시와 데이터를 완전히 분리하지 못한다. 프롬프트는 "부탁"이고, 권한·격리는 "강제"다. 방어는 모델이 틀렸을 때를 가정해 모델 바깥에 둔다.

**Q.** 심층 방어(defense in depth)는 어떤 층인가?

**A.** 한 층이 뚫려도 다음 층이 피해를 줄이도록 겹친다.

| 층 | 통제 | 모델이 속았을 때 |
|---|---|---|
| 1 입력 | 출처 표시, 필터 | 일부만 걸러짐 |
| 2 권한 | 최소권한, deny 규칙 | 할 수 있는 일 자체가 적음 |
| 3 격리 | 샌드박스, egress 제한 | 파일·네트워크 밖으로 못 나감 |
| 4 승인 | 사람 확인 | 고위험 행동만 멈춤 |
| 5 관측 | 로그, 알림 | 빨리 발견 |
| 6 복구 | 백업, 킬 스위치 | 되돌림 |

> **🧪 가설**
> "모델이 더 똑똑해지면 1층(입력 필터)만으로 충분해진다." 검증 방법은 레드팀 입력 50개를 돌려 우회율을 재는 것이다. 우회율이 0이 아니면 2~6층이 필요하다.

> **💡 PM 시선**
> 보안 요구사항은 "속지 않게 하라"가 아니라 "속아도 피해가 이 범위를 넘지 않게 하라"로 쓴다. 이 문장이 수용 기준(acceptance criteria)이 된다.

## 7-3. 최소권한은 어떻게 설계하는가?

**Q.** 에이전트 권한은 무엇부터 나누는가?

**A.** 세 축으로 나눈다. 도구(무엇을 호출하나), 스코프(어디까지 건드리나), 자격증명(누구 이름으로 하나).

| 축 | 나쁜 기본값 | 좋은 설계 |
|---|---|---|
| 도구 | 쉘 전체, 모든 MCP | 작업에 필요한 도구만 allowlist |
| 스코프 | 프로덕션 DB 쓰기 | 개발 DB, 읽기 전용 계정 |
| 자격증명 | 개발자 개인 토큰 | 에이전트 전용 서비스 계정 |

**Q.** 작업마다 권한을 따로 줘야 하나?

**A.** 그렇다. "리팩터링 에이전트"는 저장소 쓰기만, "리서치 에이전트"는 읽기와 웹만 준다. 둘 다 가진 하나의 만능 에이전트가 가장 위험하다. 개인 데이터 접근, 비신뢰 콘텐츠, 외부 통신이 한 세션에 모이면 lethal trifecta가 완성된다. 셋 중 하나를 구조적으로 끊는 것이 권한 설계의 핵심이다.

> **🔍 탐구 과정**
> 처음에는 "개발자가 쓰는 도구니 개발자 권한 그대로 주자"고 생각하기 쉽다. 그러나 에이전트는 사람보다 빠르고 지치지 않으며 속을 수 있다. 같은 계정이어도 위험은 다르다. 그래서 읽기·쓰기·삭제 권한을 분리한 별도 계정으로 시작해 필요할 때만 올린다.

> **✅ 체크포인트**
> 우리 에이전트의 DB 계정은 DROP·DELETE 권한이 있는가? 있다면 이유를 한 줄로 적을 수 있는가?

## 7-4. 샌드박스는 무엇을 막는가?

**Q.** 샌드박스는 권한 설정과 무엇이 다른가?

**A.** 권한 규칙은 "도구 호출 전" 판단이고, 샌드박스는 "프로세스가 실제로 하는 일"을 OS 수준에서 제한한다. 규칙이 문자열 매칭에 의존하므로, 우회된 명령도 샌드박스 경계에서는 막힌다.

**Q.** 격리 수준은 어떻게 고르나?

**A.** 위협에 비례해 고른다.

| 방식 | 격리 강도 | 비용·불편 |
|---|---|---|
| OS 샌드박스 | 중 | 낮음, 호환성 이슈 |
| 컨테이너(dev container) | 중상 | 설정 필요 |
| VM·클라우드 세션 | 상 | 파일 동기화 번거로움 |
| 별도 머신·계정 | 최상 | 가장 불편 |

**핵심 4요소**
1. 파일시스템: 작업 폴더만 쓰기, 홈의 `.ssh`·`.aws`는 읽기 금지
2. 네트워크 egress: 기본 차단, 필요한 도메인만 허용
3. 읽기전용 마운트: 소스는 읽기, 산출물 폴더만 쓰기
4. 자원 제한: CPU·시간·토큰 상한

> **🚫 흔한 착각**
> "컨테이너 안이니 안전하다." 컨테이너에 프로덕션 키나 `docker.sock`을 넣으면 격리는 사라진다. 격리의 가치는 안에 무엇을 넣었느냐로 결정된다.

> **🧪 가설**
> egress를 allowlist로 막으면 간접 프롬프트 인젝션의 데이터 유출 경로가 크게 줄어든다. 검증은 인젝션 문장이 든 문서를 읽혀 외부 도메인 요청이 시도되는지 프록시 로그로 확인한다.

## 7-5. 비밀은 에이전트에게 어떻게 숨기는가?

**Q.** 에이전트가 API를 호출해야 하는데 키를 줘야 하지 않나?

**A.** 키를 "보여 주지 않고" 쓰게 하는 방법이 있다. 에이전트가 `.env`를 읽으면 그 내용은 모델 컨텍스트에 들어가고, 인젝션 한 번이면 밖으로 나갈 수 있다.

| 방식 | 설명 | 평가 |
|---|---|---|
| 프롬프트에 키 포함 | 가장 쉬움 | 금지 |
| 환경변수 주입 | 프로세스가 읽음 | 쉘 접근 시 노출 |
| 프록시 주입 | 네트워크 프록시가 요청에 헤더를 붙임 | 에이전트는 키를 못 봄 |
| 단기 토큰 | 만료 15분, 범위 한정 | 유출돼도 피해 작음 |
| OIDC 발급 | 정적 키 없음 | CI에서 권장 |

**원칙 3가지**
1. 에이전트용 키는 사람용과 분리하고 권한을 줄인다.
2. 만료와 로테이션을 기본값으로 한다.
3. 로컬 비밀 파일은 읽기 자체를 막는다(7-7쪽의 `Read` deny).

> **⚠️ 실제 사례**
> Nx "s1ngularity" 공급망 공격(2025.8)에서는 악성 버전이 설치된 환경의 개발자 시크릿과 토큰이 수집 대상이 됐고, 일부 사례에서 로컬에 설치된 AI CLI 도구가 파일 탐색에 악용됐다고 보고됐다. 교훈은 개발 머신에 장기 비밀이 놓여 있으면 어떤 도구든 그것을 찾을 수 있다는 점이다.

> **🛠 실습**
> 내 저장소에서 장기 키(만료 없는 토큰) 3개를 찾아 단기 토큰이나 OIDC로 바꿀 계획을 적어 본다.

## 7-6. 승인 정책은 어떻게 나누는가?

**Q.** 모든 행동에 승인을 받으면 가장 안전하지 않나?

**A.** 반대다. 승인이 하루 수백 번이면 사람은 읽지 않고 누른다(승인 피로, Part 6). 승인은 "드물고, 구체적이고, 되돌릴 수 없는 행동"에만 쓴다.

**위험 행동 분류**

| 등급 | 예 | 정책 |
|---|---|---|
| 낮음 | 파일 읽기, 테스트 실행 | 자동 허용 |
| 중간 | 작업 폴더 내 수정, 패키지 설치 | 자동 허용 + 로그 또는 첫 1회 확인 |
| 높음 | 외부 전송, 푸시, 배포 | 매번 승인 |
| 금지 | 프로덕션 DB 삭제, 키 열람 | deny, 사람도 별도 절차 |

**Claude Code 권한 모드**(공식 문서 기준)

| 모드 | 동작 |
|---|---|
| `default` | 도구 첫 사용 시 묻는다 |
| `acceptEdits` | 작업 폴더 내 편집과 기본 파일 명령 자동 승인 |
| `plan` | 읽기만, 소스 수정 안 함 |
| `auto` | 분류기가 요청과 맞는지 검토 후 실행 |
| `dontAsk` | 묻는 호출은 전부 거부, 사전 허용만 실행 |
| `bypassPermissions` | 프롬프트 생략, 격리 환경에서만 |

> **💡 PM 시선**
> 승인 요청 수와 승인율을 지표로 본다. 승인율이 99%를 넘고 요청이 많다면 형식화됐다는 신호이므로 규칙으로 자동화하거나 아예 금지한다.

## 7-7. Claude Code 권한 규칙은 어떻게 쓰는가?

**Q.** `.claude/settings.json`에서 무엇을 막고 무엇을 여는가?

**A.** `permissions`의 `allow`와 `deny`에 규칙을 적는다. 평가 순서는 deny, ask, allow이며 먼저 맞는 것이 결정한다. 따라서 deny에 있으면 allow로 예외를 만들 수 없다. 어느 설정 파일에서든 deny가 있으면 막힌다.

```json
{
  "permissions": {
    "defaultMode": "default",
    "allow": [
      "Bash(npm run *)",
      "Bash(git commit *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./secrets/**)",
      "Bash(git push *)",
      "Bash(curl *)"
    ]
  }
}
```

**주의할 점**
1. `*`는 하위 명령 뒤에 둔다. `Bash(git push *)`처럼 쓴다.
2. 문자열 규칙은 우회될 수 있다. `git -C . push`나 `sh -c` 안의 명령은 안 걸릴 수 있다고 문서가 명시한다. 네트워크는 샌드박스 허용 목록으로 보완한다.
3. 비밀 파일 차단은 `Read` deny로 한다. `.claudeignore`는 효과가 없다고 문서에 적혀 있다.
4. 프로젝트의 `allow`는 워크스페이스 신뢰 수락 후에만 적용된다. 낯선 저장소의 신뢰 대화상자를 읽고 수락한다.
5. 조직은 managed settings로 규칙을 강제하고, `permissions.disableBypassPermissionsMode`를 `"disable"`로 둘 수 있다.

> **🛠 실습**
> 위 JSON을 샌드박스용 저장소에 넣고 `/permissions`로 규칙이 보이는지 확인한다. 그다음 `.env` 읽기를 시켜 거부되는지 본다.

## 7-8. 샌드박스와 훅은 어떻게 겹쳐 쓰는가?

**Q.** 규칙이 우회될 수 있다면 무엇으로 보완하는가?

**A.** 샌드박스를 켜고, 필요하면 훅으로 직접 검사한다. 샌드박스는 `/sandbox` 명령이나 설정의 `sandbox.enabled`로 켠다(기본은 꺼짐). macOS는 Seatbelt, Linux·WSL2는 bubblewrap을 쓴다.

```json
{
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "allowUnsandboxedCommands": false,
    "filesystem": { "denyRead": ["~/.ssh", "~/.aws"] },
    "network": { "allowedDomains": ["github.com", "*.npmjs.org"] }
  }
}
```

**한계(공식 문서)**
1. 쉘 명령만 감싼다. 파일 도구, WebFetch, MCP 서버, 훅은 밖에서 실행된다.
2. 기본 읽기 정책은 `~/.ssh` 같은 자격증명 파일을 막지 않으므로 직접 deny한다.
3. `allowUnsandboxedCommands`를 `false`로 하지 않으면 실패한 명령을 샌드박스 밖에서 재시도할 수 있다.

**훅.** `PreToolUse` 훅은 도구 실행 전에 스크립트를 돌려 stdin의 JSON(`tool_name`, `tool_input`)을 검사한다. 종료 코드 2면 호출이 차단되고 stderr가 Claude에게 전달된다.

```json
{ "hooks": { "PreToolUse": [ {
  "matcher": "Bash",
  "hooks": [ { "type": "command",
    "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/guard.sh" } ]
} ] } }
```

> **🔍 탐구 과정**
> 훅은 허용 규칙보다 먼저 막을 수 있지만, 훅의 `allow`가 deny 규칙을 뒤집지는 못한다. 그래서 금지는 deny, 맥락 의존 검사는 훅으로 나눈다.

## 7-9. MCP 서버는 무엇을 보고 도입하는가?

**Q.** 인기 있는 MCP 서버를 그냥 설치해도 되나?

**A.** 안 된다. MCP 서버는 에이전트에게 도구와 컨텍스트를 주입하는 외부 코드다. 공식 문서도 직접 만들거나 신뢰할 수 있는 제공자의 서버를 권하며, Anthropic은 MCP 서버를 보안 감사하지 않는다고 밝힌다.

**도입 심사 체크리스트**

| 항목 | 질문 |
|---|---|
| 출처 | 제작자가 누구인가, 저장소가 활발한가 |
| 권한 | 읽기 전용 모드가 있는가, 스코프가 최소인가 |
| 인증 | OAuth 스코프 범위, 토큰 저장 방식 |
| 도구 설명 | 설명문에 숨은 지시가 있는가(tool poisoning) |
| 버전 | 고정 가능한가, 업데이트 시 재검토하는가 |
| 데이터 | 어떤 데이터가 서버로 나가는가 |
| 실행 | 로컬 프로세스인가 원격인가, 샌드박스 가능한가 |

> **⚠️ 실제 사례**
> postmark-mcp(2025.9)는 정상 서버처럼 배포되다 이후 버전에서 이메일을 외부로 복사하는 코드가 들어간 것으로 보안 연구자들이 보고했다. 교훈은 "한 번 심사"가 아니라 버전 고정과 업데이트 재심사다.

## 7-10. 입력·출력 가드레일과 로그는 어떻게 두는가?

**Q.** 가드레일은 모델 안에 넣는가, 밖에 두는가?

**A.** 밖에 둔다. 프롬프트 지시가 아니라 코드로 검증한다.

| 위치 | 예 | 한계 |
|---|---|---|
| 입력 | 출처 라벨, 길이 제한, 패턴 탐지 | 우회 가능, 확률적 |
| 도구 인자 | 스키마 검증, 허용 값만 통과 | 결정적, 가장 믿을 만함 |
| 출력 | 비밀 패턴 마스킹, URL·이미지 도메인 제한 | 유출 경로 일부 차단 |
| 행동 | 금액·건수 상한, 속도 제한 | 폭주 방지 |

도구 인자 검증이 가장 강하다. 예를 들어 SQL 도구는 임의 쿼리 대신 읽기 전용 뷰만 받도록 한다.

**Q.** 무엇을 기록하고 어떤 지표를 보나?

**A.** 누가(에이전트 ID), 무엇을(도구·인자), 언제, 승인 여부, 결과를 남긴다. 로그에 비밀이 들어가지 않게 마스킹한다.

| 지표 | 의미 |
|---|---|
| 거부(deny) 발생 수 | 시도된 위험 행동 |
| 승인율·승인 대기 시간 | 승인 피로 |
| egress 차단 건수 | 유출 시도 후보 |
| 세션당 비용·토큰 | 폭주·DoS 징후 |

> **🛠 실습**
> 에이전트 도구 호출 로그에 필수 필드 5개를 정하고, 알림이 필요한 임계값 2개를 적는다. Claude Code는 OpenTelemetry 지표로 사용량을 모니터링할 수 있다.

## 7-11. 사고가 나면 어떻게 멈추고 되돌리는가?

**Q.** 방어를 다 해도 사고는 나지 않나?

**A.** 난다. 그래서 설계의 마지막 층은 "멈추고 되돌리는 능력"이다.

> **⚠️ 실제 사례**
> Replit 에이전트 사건(2025.7)에서 한 사용자가 코드 동결(code freeze)을 지시했음에도 에이전트가 프로덕션 데이터베이스를 삭제했다고 공개적으로 알렸다. Replit CEO는 사과하고, 개발·프로덕션 DB 분리와 롤백·계획 전용 모드 같은 안전장치를 강화하겠다고 밝혔다. 교훈은 "지시"는 통제가 아니며, 프로덕션 접근과 복구 수단이 구조로 분리돼야 한다는 점이다.

출처: 언론 보도 및 Replit CEO 공개 발언(2025.7).

**Q.** 무엇을 미리 준비하나?

**A.**

| 준비 | 기준 |
|---|---|
| 킬 스위치 | 에이전트 키 폐기, 세션 중단을 1분 안에 |
| 환경 분리 | 개발·스테이징·프로덕션 계정 분리 |
| 백업 | 자동 백업과 복원 훈련(복원해 본 적이 있는가) |
| 롤백 | 모든 변경이 git 커밋, 마이그레이션은 되돌림 스크립트 |
| 변경 동결 | 동결 기간에는 쓰기 권한 자체를 회수 |

> **🧪 가설**
> "백업이 있으니 안전하다"는 틀릴 수 있다. 복원 시간(RTO)을 실제로 측정하면 가설을 검증할 수 있다. 측정한 적이 없다면 백업은 믿음일 뿐이다.

> **🗣 토론**
> 지금 에이전트를 멈추려면 몇 단계가 필요한가? 누가 그 권한을 갖는가?

## 7-12. 통제 강도는 어떻게 결정하는가?

**Q.** 모든 곳에 최고 수준 통제를 걸어야 하나?

**A.** 아니다. 통제는 비용이고 생산성을 깎는다. 영향도(피해 크기)와 가역성(되돌릴 수 있나)으로 강도를 정한다.

| 상황 | 영향 | 가역성 | 권장 통제 |
|---|---|---|---|
| 개인 토이 프로젝트 | 낮음 | 높음 | 기본 모드 + 비밀 차단 |
| 팀 저장소 코딩 | 중 | 중 | 샌드박스 + deny 규칙 + 훅 |
| 고객 데이터 접근 | 높음 | 낮음 | 읽기 전용 계정 + 승인 + 로그 |
| 프로덕션 변경 | 매우 높음 | 낮음 | 에이전트 직접 접근 금지, 파이프라인 경유 |

**의사결정 질문 3개**
1. 이 에이전트가 최악으로 행동하면 무엇이 사라지는가?
2. 그것을 한 시간 안에 복구할 수 있는가?
3. 통제를 추가하면 하루 몇 분이 늘어나는가?

> **📌 핵심 정리**
> - 프롬프트는 부탁, 권한·격리는 강제다. 모델 바깥에 6겹을 쌓는다.
> - 최소권한은 도구·스코프·자격증명 3축으로 나눈다.
> - 승인은 드물고 구체적인 고위험 행동에만 쓴다.
> - Claude Code는 permissions(deny 우선), sandbox, hooks를 겹쳐 쓴다.
> - 마지막 방어선은 킬 스위치와 검증된 복구다.
