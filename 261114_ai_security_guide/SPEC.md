# 집필 규격서 — 「바이브코딩 · 에이전틱 개발 시대의 보안」 100페이지 교안

## 0. 독자와 톤
- 독자: 20년차 PM/CPO 출신 강사가 AI Agent 개발자 과정·PM 강의에서 쓰는 교안. 수강생 = PM, 기획자, 주니어~시니어 개발자, 1인 SaaS 빌더. **보안 전문가가 아님.**
- 언어: 항상 **한국어**(고유명사·코드는 영어 그대로). 문체: "~입니다/~합니다" 대신 간결한 "~다/~이다" 또는 명사형 종결 혼용 가능하나 **한 파트 안에서 통일**.
- 핵심 원칙 3가지(반드시 반영):
  1. **질문과 답변(Q&A) 형태**: 페이지 본문을 `**Q.** …` / `**A.** …` 쌍 중심으로 구성한다.
  2. **유저(수강생·사용자)의 문제 → 가설 → 검증** 흐름. 경쟁/대안(도구·접근법)을 비교해 "왜 이걸 고르는가"를 보여준다.
  3. **결론보다 과정·탐구**: "처음엔 이렇게 생각하기 쉽다 → 왜 틀렸나 → 어떻게 확인했나 → 배운 점" 구조를 자주 쓴다.
- 프레임: Product Trio(PM·디자이너·엔지니어) 관점 + 데이터 드리븐(어떤 지표/로그로 확인하나) + 그로스 관점(보안이 신뢰·전환·리텐션에 미치는 영향)을 적절히 녹인다. 단, 억지로 모든 페이지에 넣지 말 것.

## 1. 분량·페이지 단위 (가장 중요)
- 교안은 **고정 페이지(A4)** 로 조판된다. 각 파트 파일은 페이지를 **한 줄 `<!--page-->`** 로 구분한다. **지정된 페이지 수를 정확히 지킬 것.**
- 한 페이지 = 공백 포함 **약 900~1,300자**(표·코드·박스 환산 포함). 500자 미만 금지, 1,500자 초과 금지. 넘치면 빌드가 글자를 줄이거나 오버플로우로 경고한다.
- 코드블록은 페이지당 최대 18줄, 한 줄 70자 이내. 코드 주석은 한국어 가능.
- 다이어그램이 필요하면 **ASCII 전용(영문·기호만)** 코드블록으로 그리거나 표로 대체한다. 한글이 들어간 ASCII 박스 다이어그램 금지(폭이 깨짐). 이미지·mermaid 금지.

## 2. 파일 형식
- 출력 파일: `261114_ai_security_guide/parts/partNN.md` (NN = 01~10). **당신 파트 파일 하나만** 쓴다. 다른 파일 수정/커밋/푸시 금지.
- 각 파트의 **첫 페이지 = 파트 오프너**:
  ```
  # Part N. 파트 제목
  > **🎯 학습 목표** 3개 불릿
  **이 파트의 핵심 질문** (번호 목록 3~4개)
  **이 파트의 지도** (페이지별 한 줄 요약 표: | 쪽 | 질문 | )
  ```
  나머지 페이지는 `## N-k. 페이지 제목` (제목은 가급적 질문형)으로 시작. `#`는 오프너에서만, `###`는 필요 시 페이지 내 소제목.
- **박스(callout) 문법**: 인용문(`>`)의 첫 줄을 아래 라벨 중 하나로 시작한다 (빌드가 색 박스로 변환).
  - `> **🎯 학습 목표**` / `> **💡 PM 시선**` / `> **🧪 가설**` / `> **⚠️ 실제 사례**` / `> **🛠 실습**` / `> **✅ 체크포인트**` / `> **🗣 토론**` / `> **🔍 탐구 과정**` / `> **🚫 흔한 착각**` / `> **📌 핵심 정리**`
- 표는 GFM 표. 한 표당 최대 7행·4열 권장(세로 공간 주의).
- 출처가 있는 사례는 페이지 끝에 `출처: …` 로 시작하는 한 줄 단락을 둔다(작은 글씨로 자동 처리). 가능하면 기관·문서명·연월을 적는다.
- 파트마다 **최소** 포함: 실제 사례 박스 2개 이상, 가설 박스 2개 이상, 실습/토론 박스 2개 이상, 마지막 페이지에 `> **📌 핵심 정리**` + 다음 파트로 이어지는 질문 1개.

## 3. 사실성 규칙 (보안 교안이므로 엄격)
- 오늘은 **2026-11-14**. 보안·AI 도구는 빠르게 변한다. 사건·CVE·버전·수치·도구 기능은 **WebSearch/WebFetch로 확인**한 뒤 쓴다.
- 확인하지 못한 CVE 번호·통계 수치·날짜는 **쓰지 않는다**. 불가피하면 `(확인 필요)` 표기. 임의의 통계(예: "73%의 …")를 지어내지 말 것. 수치는 출처와 함께만.
- 실제 사고는 사실만(누가/무엇이/어떻게/교훈). 피해자 비난, 추측성 서술 금지. 개인정보 포함 금지.
- 이미 아는 대표 사례 후보(검증 후 사용): Replit 에이전트 프로덕션 DB 삭제 사건(2025.7), Amazon Q Developer VS Code 확장 악성 프롬프트 삽입(2025.7), Nx "s1ngularity" 공급망 공격(2025.8), npm "Shai-Hulud" 웜(2025.9), postmark-mcp 악성 MCP 서버(2025.9), GitHub MCP 간접 프롬프트 인젝션(Invariant Labs, 2025.5), Supabase MCP 데이터 유출 시연(2025.7), EchoLeak(M365 Copilot, CVE-2025-32711), Cursor CurXecute/MCPoison, Pillar "Rules File Backdoor", slopsquatting(환각 패키지), Lovable RLS 이슈(CVE-2025-48757), Tea 앱 유출(2025.7), Veracode GenAI 코드 보안 보고서(2025), OWASP Top 10 for LLM Applications 2025, OWASP Top 10 for Agentic Applications(2025.12), Simon Willison "lethal trifecta", Anthropic의 AI 오케스트레이션 사이버 공격 보고(2025.11) 등. 2026년 상반기 이후 신규 사건/표준이 있으면 검색해 반영.
- **방어 중심 교육 자료**다. 공격 기법은 원리·시연 수준(예: 짧은 인젝션 문장 예시, 취약 코드 vs 수정 코드)까지만. 실제 무기화된 익스플로잇, 악성코드 완성본, 우회 레시피는 쓰지 않는다.

## 5. 파트별 범위 (중복 금지 — 경계 지키기)
**Part 01 (10쪽) 위협 지형**: ① 바이브코딩/에이전틱 개발 정의와 공격 표면 변화(코드 작성자가 사람→AI) ② 대표 사고 연대기(2025~2026) 표 ③~⑤ 사고 3건 심층 탐구(Q&A로 "무슨 일이/왜 가능했나/무엇을 막았어야") ④ 책임 공유 모델: 누가 무엇을 책임지나(모델 제공사·도구·개발자·PM) ⑤ 위협 모델링 입문(STRIDE 간단판, 자산·행위자·경로) ⑥ "보안 = 속도 저하"라는 가설 검증, 보안과 그로스(신뢰·전환) ⑦ 이 교안 전체 지도. 기술 상세는 뒤 파트에 맡기고 여기선 '왜/무엇'.
**Part 02 (10쪽) 기초 8개념**: CIA 3요소, 인증(Authentication) vs 인가(Authorization)와 세션/JWT/OAuth 개념, 비밀(API키·토큰) 관리와 .env, 암호화(전송/저장)·해시, 입력 검증과 인젝션 개념(SQLi/XSS/CSRF/SSRF를 PM 눈높이로), 최소권한, 로깅·감사, OWASP Top 10(웹, 2021/최신판) 한 장 요약, 안전한 기본값. 각 개념마다 "바이브코딩에서 어떻게 깨지는가" 1줄.
**Part 03 (10쪽) AI 생성 코드 취약점**: AI 코드 보안 연구 현황(출처 있는 것만), 취약 패턴 사례(하드코딩 시크릿, SQL 문자열 결합, 약한 인증/세션, 과도한 CORS, 검증 누락, 에러 노출, 안전하지 않은 기본 설정), BaaS 설정 실수(Supabase RLS·Firebase rules·공개 버킷), 환각 패키지(slopsquatting), '취약 코드 vs 수정 코드' 비교 3개, 프롬프트로 보안 품질 올리기(보안 요구사항을 명세에 넣는 법), 사람이 하는 5분 보안 리뷰 체크리스트. (의존성·CI 공급망 일반론은 Part 04)
**Part 04 (10쪽) 공급망**: 의존성 위험(typosquatting, 계정 탈취, 설치 스크립트), 2025 npm/Nx 사건 교훈, lockfile·버전 고정·최소 릴리스 연령 정책, SBOM·SCA(Dependabot/Snyk/Socket/OSV 등 비교 표), 환각 패키지 방어, GitHub Actions 보안(권한 최소화, 핀 고정, pull_request_target 위험), 시크릿 관리(vault/OIDC/로테이션, 유출 시 대응), 코드 서명·출처증명(provenance) 개념, 에이전트가 의존성을 설치할 때의 가드. 
**Part 05 (12쪽) LLM 앱 보안**: LLM 앱 아키텍처와 신뢰 경계, OWASP Top 10 for LLM 2025 전체 10항목 지도, 직접/간접 프롬프트 인젝션(원리와 짧은 예시), 왜 근본적으로 어려운가(지시와 데이터의 미분리), lethal trifecta(개인데이터·비신뢰 콘텐츠·외부 통신), 데이터 유출 경로(마크다운 이미지, 링크, 도구 호출), 출력 처리 불량(Improper Output Handling), RAG 포이즈닝·벡터/임베딩 취약점, 시스템 프롬프트 유출, 과도한 지출/DoS(Unbounded Consumption), 탐지·완화 계층 방어, 사례(EchoLeak 등) 탐구, 평가(red-team 테스트셋) 입문.
**Part 06 (12쪽) 에이전트·MCP**: 에이전트가 일반 LLM 앱과 다른 점(도구·메모리·자율성), 에이전트 위협 모델(권한 상승, 도구 오남용, 메모리 오염, 연쇄 실패), OWASP Top 10 for Agentic Applications 지도, MCP 아키텍처와 인증/인가(OAuth), MCP 위협(tool poisoning, rug pull, confused deputy, 악성 서버·사칭, 과도한 스코프), 사례(GitHub MCP·Supabase MCP·postmark-mcp), 코딩 에이전트 고유 위협(Rules/설정 파일 백도어, 프로젝트 설정 자동 실행, .env 읽기, 위험한 쉘 명령, Amazon Q 사례), 멀티 에이전트 신뢰와 에이전트 ID/자격증명, Replit DB 삭제형 '자율성 사고', 휴먼 인더루프의 한계(승인 피로). 방어 설정의 상세는 Part 07.
**Part 07 (12쪽) 방어 설계**: 방어 심층(defense in depth) 원칙, 최소권한 설계(도구·스코프·자격증명 분리), 샌드박스(컨테이너·VM·네트워크 egress 제한·읽기전용 마운트), 승인 정책(권한 모드, allowlist/denylist, 위험 행동 분류), 시크릿 격리(에이전트에게 키를 직접 주지 않기·프록시 주입·단기 토큰), Claude Code 같은 코딩 에이전트의 권한/훅/설정 실습(일반 원리 + Claude Code 예시; 최신 공식 문서 확인), MCP 서버 도입 심사 체크리스트, 입력/출력 가드레일, 로깅·감사 추적·모니터링 지표, 킬 스위치·롤백·백업(Replit 교훈), 보안 vs 생산성 트레이드오프 의사결정 매트릭스.
**Part 08 (8쪽) 자동화 파이프라인**: 보안 도구 지형(SAST/DAST/SCA/Secret scan/IaC scan; Semgrep, CodeQL, Gitleaks, Trivy, OSV-Scanner, Snyk, GitHub Advanced Security 등 비교 표—경쟁/대안 관점), pre-commit→CI→배포 단계별 게이트, AI 보안 리뷰 에이전트(예: Claude Code security review 류 기능 — 최신 확인), 리뷰 에이전트 프롬프트 템플릿 3개, 오탐/미탐과 사람 개입, LLM 앱 레드팀·평가 하네스(promptfoo류 개념), 보안 지표(MTTR, 시크릿 유출 건수 등)와 데이터 드리븐 운영.
**Part 09 (8쪽) 거버넌스·규제·인시던트**: 한국 개인정보보호법 핵심(수집·이용·위탁·국외이전, 유출 통지) + GDPR 개요 + EU AI Act 개요(기본 개념만, 법률 자문 아님 명시, 최신 확인) + ISMS-P/SOC 2 개요, AI 도입 정책(허용 도구·데이터 분류·사내 가이드), 벤더/모델 제공사 리스크 평가(데이터 보존·학습 사용 여부), 인시던트 대응 6단계와 런북, 포스트모템(비난 없는 회고), PM의 보안 로드맵·백로그 운영(리스크 우선순위, 보안 부채), 보안을 제품 신뢰·그로스로 연결.
**Part 10 (6쪽) 랩·부록**: 핸즈온 랩 5개(① 시크릿 유출 탐지·로테이션 ② 취약 바이브코딩 앱 리뷰 ③ 간접 프롬프트 인젝션 방어 실험(안전한 로컬 샌드박스) ④ MCP 서버 심사 ⑤ 에이전트 권한 정책 설계) — 각 랩은 목표·준비물·단계·확인 기준·토론, 종합 체크리스트(출시 전 보안 점검 30항목 표), 용어집(40개 내외 표), 참고자료(공식 문서·표준·읽을거리 목록), 확인 퀴즈(O/X·객관식 15문항+해설), 강사용 팁(수업 운영안).
